# ブラックジャックの部品図と環状線

抽選アプリ（daigakusai-lottery）の学習ページを、このブラックジャックに当てはめたものです。上のタブで図の細かさ（C4 モデル）を切り替えます。

| 段 | 見るもの | 元にしたもの |
|---|---|---|
| 1 コンテキスト | simple_blackjack を1つの箱にして、遊ぶ人・タスク A/B/C の学生・授業の担当・GitHub・VS Code・Excel とのやりとり | main の `docs/map` のコンテキスト図 |
| 2 コンテナ・コンポーネント | dealer.py・autodealer.py の2つのプログラムと、import される card.py・players/。行を押すとコード | main の `docs/map` の部品図 |
| 3 環状線（コード） | 1ラウンドを1周として、駅ごとの行・変数・旗。部品図（駅 × 役割） | learning の `docs/blocks` |

デプロイは無いので、デプロイ図は作っていません。1 と 2 の図のデータ（箱・行・矢印）は `ring.src.html` の `CTX`・`C4B`・`C4E` にあります。

1 と 2 の図の上の「流れで見る」には、タスクとは別に **dealer.py で1周**（`P`。キーボードで 100 → hit → stand → 0 と打った1ラウンド）と **autodealer の1手**（`Q`。プレイヤーのプログラムが hit か stand かを決める仕組み）がある。どちらも、最初に準備の帯から出る **実行前の準備**（起動するまで。紫の a・b・c…）があり、そのあとに実行の流れ（1・2・3…）が続く。手順ごとに `st`（3 環状線の駅）を持ち、手順から環状線の同じ駅へ、環状線の駅から 2 の図の同じ手順へ行き来できる。dealer.py の流れの値と実行時の呼び出しは、`build.py` が本物の dealer.py を決めた答えで流して記録したもの（`trace_dealer`）。

「流れで見る」には、ゲームが終わる所だけを取り出した **勝って終わる**（`W`。勝ち逃げ: 1200 まで勝ち、次の place_bet が 0 を返して return / dealer.py は exit()）と **負けて終わる**（`L`。残高 0: 駅 20「残高が 0 か」が真になって return 0, 26 / dealer.py は break。バーストで 0 になる別の道も）もある。どちらも autodealer と dealer.py のコードを並べて、違うのは最後の return と exit()・break だけだと分かるようにした。値は環状線 01 のルート「勝ち逃げで終わる」「負けて終わる（player_simple のまま・最後のラウンド）」を本物で流したもので、流れの上のボタンからそのルートへ行ける。2 の図の dealer.py の箱には、そのための行 `if player_balance <= 0:` がある。autodealer ではゲームが終わっても次があるので、流れの最後に「次のゲーム（Player(1000) を作り直す。global の deck と round は続き）」と「MAX 回のあと（結果の1行）」の手順もある。

W と L の下には **変数の変遷** がある。`build.py` の `trace_ending` が、本物の `python3 autodealer.py` と同じ動き（MAX = 4000 のまま）を、1ゲーム目が勝ち逃げ／残高 0 で終わる乱数の種で流し、その前のラウンド・最後のラウンド・__main__ に戻る所・次のゲームの始まり・4000 回のあとの行を、変数の値と型（int・tuple…）、if を本当に評価した真偽、その行で入った値、実際に次に動いた行と一緒に記録する。ページでは「なぜ 0 を返すのか」「なぜ 0 で終わるのか」「返した値はどこへ」「次はどうなるか」ごとに、値が生まれた行（リテラル 1000・1100・0）から引数・戻り値・if・return を通って次のループへ行くまでをカードで横に並べ（`LINEAGE`）、その下に通った行を全部表で出す。カードと表のコードを押すと、その行が入っている関数（関数の外なら一番外の文）の全体が出て、外から順にどの def・for・while・if の中にいるかが分かる（`enclosing`・`fnView`）。

1 と 2 の図の上の「タスクで見る」で A（分析）・B（戦略）・C（改造）を選ぶと、そのタスクの流れが番号つきの矢印で重なります。関係しない箱は薄くなり、下に手順の一覧が出ます（← → で前後）。2 の図では、手順ごとに関係するコードも出ます。流れのデータは `ring.src.html` の `TASKS` にあります。

- 手順は2種類。`p: true` は **実行前の準備**（並列・どれからでもよい。紫で a・b・c…）、それ以外は **実行の流れ**（順番。タスクの色で 1・2・3…）
- 「autodealer の1手」だけは準備が2段ある。`p: true` が **テストの準備**（python3 autodealer.py で1回。紫で a・b・c…: 起動・山札・players/ の import・MAX 回のくり返し）、`p: 2` が **本番の1周の準備**（game() の中。橙で ア・イ・ウ…: ゲームごとにプレイヤーを作る、ラウンドごとに手札を空に・place_bet・check_shuffle と配る）。見出しはタスクの `prepTitles`
- タスク A・B・C とは別に **タスク外の改修**（`X`。灰色で 外1・外2…）がある。どのタスクの結果にも効くので、教材の側で直しておきたい所（例: 無効な掛け金の -1 が平均に混ざる 緊1）。タスクの手順には入れない
- `code` は手順で見せるコードで、`[ファイル, 探す文字列, 行数, 光らせる行, 変える行, 前に足す行数, 印の文字]`。変える行は橙で「← 変える」などが付く。同じ文字列がファイルに2回以上あるときは `"if player_balance <= 0:#2"` のように `#何番目` を付ける
- `ex` は変更の例（`+` 足す・`-` 消す）。B・C の例は、このページを作るときに実際に入れて autodealer.py で流し、止まらずに動くことを確かめた
- `where` は、その変更・手順が効く所（`"Q:ラベルの頭"` で一手の流れの手順、`"s8"`・`"r02:t3"` で環状線の駅、`"route:stopwin"` で環状線 01 のルート）。手順の下に「この変更が効く所」として出て、3 環状線の駅にも、その駅を変えるタスクの手順が出る
- 判断の部分の大事な行（`KEYLINES`）には、その行が一手のどこに当たるか（勝ち逃げの判断・ゲームを終える一手・答えを返す…）と、手順・駅・ルートへのボタンが付く
- `rt` は実行時の呼び出し（`autodealer.game:87 -> players.player_simple.BlackjackPlayer.input` のような、モジュール.クラス.メソッド）。`build.py` が本物を流して記録した中から探して出す

2 の図では、1ラウンドの流れを **dealer.py の箱に1回だけ** 書いてある。autodealer.py の `game()` はその流れを関数に入れたもので、箱には dealer.py と違う所（±: print → printx・exit/break → return・配る前の check_shuffle・turns・Player を引数で）だけを書き、「while True: … dealer.py と同じ」の行から dealer.py の箱へ線でつなぐ。本物の差分は `build.py` が difflib で比べて埋め込み（`dealer_diff`）、game の箱を押すと出る。

3 環状線の駅の「旗の荷物」の見出しの「出どころのソース: オン／オフ」をオンにすると、荷物とパラメータの値ごとに **出どころ**（「←」の行）が出る（オフが既定。選んだ方は覚えておく）。`build.py` の `run_route` が、1行実行するごとに荷物とプレイヤーの self.… を見比べ、変わっていたら直前に実行した行とその駅を記録する。戻り値なら、受け取った行（例: autodealer.py:57 `bet_amount = player.place_bet(…)`）と、返した行（player_simple.py:86 `return bet_amount`）の両方を出す。駅のボタンでその駅へ、行番号を押すとその行が入っている関数の全体が出る。ゲームの前から決まっている値（round・len(deck)・penetration）は import のときの行を出す。

パラメータの折りたたみの中には、駅によって **参考実装**（「参考実装: オン／オフ」で出す。オフが既定）（`REFIMPL`。まだコードに無いが、その駅に足せるパラメータ）が出る: 掛け金を聞く（retreat_balance・bet_ratio）、掛け金を確かめる（MIN_BET・MAX_BET）、山札の残り（NUM_DECKS）、hit か stand か（weak_threshold）、ディーラーが 17 まで引く（DEALER_STAND・HIT_SOFT17）、点数を比べる・残高を動かす（BJ_PAYOUT）。既定値と型・置き場・足したら使う行・タスク・変更の例に加えて、足すロジックの仕組み（順番）・数字の例・ねらい・注意（`REFLOGIC`）が付く。例はこのページを作るときに全部を同時に入れて autodealer.py を流し、止まらずに動くことを確かめた。

また「旗の荷物」の下には、折りたたみの **パラメータ** がある。この駅を出るときのプレイヤーのインスタンスの `self.…`（stop_balance・unit_bet・hit_threshold・balance・hand・round・dealer_card…）と、game()・autodealer の設定（initial_balance・penetration・is_print）を、値と型つきで出す（`build.py` の `run_route` が荷物と一緒に記録）。その駅で実行した行に出てくるものは色が付き、判定（if に使った）・入れた（代入）・読んだ の行が並ぶ。置き場（例: player_simple.py:5 `unit_bet = 100` → __init__ の既定値 → self.unit_bet）も出る。使った行の行番号を押すと、その行のすぐ下に、行のまわり（入っている関数の全体）が出る。参考実装にも「今のコードで入れる所」の行がある。タスク A で変えるパラメータは、タスク A の手順の順（stop_balance・撤退条件・unit_bet・hit_threshold・MAX・initial_balance、設定の penetration）に並び、タスクの印（環状線をそのタスクで絞る）と「手順 b →」（2 の図のその手順へ）が付く。撤退条件のように複数のタスクの準備に出てくるものは、全部のタスクの印と「タスク A・B で重なる」が付く（`paramTasks`。タスクの準備の手順のラベルから探す）。game() の中に無い MAX と撤退条件も、ソースの値と、使う所（環状線 02・駅 3 の参考実装）へのボタンで出す。

3 環状線の上の **タスクで絞る**（なし・A・B・C・タスク外）を選ぶと、そのタスクが関係する駅だけが色の輪で囲まれ、駅名に手順の番号（`B3`・`Bb` など。小文字は準備）が付き、ほかの駅と旗は薄くなる（`taskRel`）。関係は、タスクの手順の `st`・`where`、`where` に書いた一手の流れの手順（`"Q:…"`）の駅、`issue` の旗の駅から集める。下の表に駅ごとの手順（押すと 2 の図のその手順へ）とルートが出て、駅のコードでは、そのタスクで変える行に「← … で変える」が付く。2 の図のタスクから環状線へ跳ぶと、同じタスクで絞った状態になる。

「タスクで絞る」の **参考実装** を選ぶと、参考実装が動く駅を環状線に出す（`REFFIRE`）。**発火** = その駅を通るたびに足した行が判定・計算する所（例: retreat_balance は駅 3、NUM_DECKS は駅 5 と 21）、**判定** = その手前で条件を見る所（BJ_PAYOUT の駅 18）、**定義** = 値を決める行が動く所（ファイルの上の行なので、環状線 02 の起動の準備・プレイヤーを読み込む駅に1回）。名前を押すと、その駅のパラメータの参考実装を開く。

「タスクで絞る」の **置き場所を探す** は、自由に考えたアイデア（タスク B・C）を、どの駅・ファイル・関数・行に入れればいいかまで絞る道具。1 タスク（B = players/ のファイル、C = autodealer.py）→ 2 いつ動くか（`TIMINGS`。ゲームの始め・掛け金・hit/stand・精算…。B ではプレイヤーのメソッドが呼ばれないタイミングは「B では無理」と近い所を出す）→ 3 材料（`MATS`。その値が手に入る最初の駅。今の駅でまだ無いものは ✗）を選ぶと、駅・ファイル・関数・入れる行（押すと関数の全体）・この駅が使うファイル・この駅の参考実装・タスクの手順が出て、旗がその駅へ動き、駅のコードに「← アイデアをここに入れる」が付く。アイデアのメモはブラウザに残る。駅ごとに使っているファイル・関数の表（全ルートの本物の記録から）も付く。

材料（`MATS`）には、今どこにあるか・今の使われ方（ソースから探した代入・判定・引数・return・読む の行と、その行を通った駅 `matUses`）・外す／無効にする・置き換え・併せて使う・変えると今の駅のロジックがどう変わるか・変える順番 が付き、行番号を押すとそのカードの中に関数の全体が出る。「材料の説明: オン／オフ」でカードを出し入れできる（オフが既定）。材料には値（変数・引数）のほかに **メソッド**（`METHODS`。駅で呼ばれる入れ物で、今は少ししか使っていない・別の使い方ができるもの: B は __init__・place_bet・start_turn・receive_hand・look_dealer_hand・input・finish_dealer_hand・notify_result・__str__、C は game・check_shuffle・turn_end・printx・Card.sum・Card.is_soft・Card.is_blackjack）があり、呼ばれる駅（本物の記録から `methodStations`）・今していること・使っていない／改造の余地・このメソッドでできること・別ファイル／別の駅・注意 が出る。「4. メモ」には、まだコードに無い「こういう変数があればいいかも」を、名前・初期値・ロジックに分けて足せる（ブラウザに残る）。**プロンプトのテンプレート**（`buildPrompt`）は、アイデア・タスク・駅・ファイル・関数の今のコード・環状線の前後の駅・選んだ材料の今の使われ方・ほかの材料・メモした変数・この駅の参考実装を書き出し、「まず既存の材料・ステートメント・判定で叶えられるか → 足りなければメモの変数をどこで定義・更新・判定するか → 順番に変更 → 環状線の流れの変化 → 今の決まりを壊さないか」を頼む形にする（コピーのボタン付き）。コードの全体は「全部プロンプトに貼る」（関係するファイルの全文を行番号つきで最後に付け、照らし合わせてから考えるよう頼む）・「ファイルごとに選ぶ」（ファイルごとにアップロードか貼るかを選ぶ。アップロードするファイルは「個別にアップロードしてほしいファイル」として一覧に出し、プロンプトの最初にも書く。アップロードの上限に入りきらないファイルは貼る）・「入れない」（無いときは推測せずにファイルを求めるよう頼む）から選べる。ファイルの情報は折りたたみ（最初は閉じていて、見出しの下に「アップロード: … ／ 貼る: …」か「6 ファイル（全部貼る）」を出す）。開くと、各ファイルのインポート文（ファイルごとの折りたたみ「インポート 6 件」。行番号を押すとまわりのコード）と、なぜ要るか（横にスクロールできる。どのファイルのどのインポートで読み込まれるか）、「この1ファイルをコピー」が付き、プロンプトにも「ファイルとインポート」の節が入る。ファイルは B なら autodealer.py・card.py・players/player_simple.py、C ならルールが全員に効くので players/ の今ある .py 全部（player_random など）に dealer.py・player.py を足す。参考実装は、仕組み・例・ねらい・注意（player_random が範囲外の掛け金で -1 を返す、など）もプロンプトに入る。お願いには、players/ の全員が変更のあとも動くかと、テスト（有効・無効・境目）も入っている。

アイデア・メモした材料・自分の設計は、タスク B と C で別々に持つ（`tget`・`tset`）。「例を読み込む」は、そのタスクの入力を置き換える（足さない）。「タスク B の入力を全部消す」もある。

パレットの「コードから駅を探す」タブ（`findSnippet`）は、コードの一部（1行でも数行でも）を貼ると、どのファイルの何行目か・どの関数か・どの駅か（全ルートの実行記録から。環状線 02 の駅も）を出す。このページのコードを行番号つきでコピーしたもの、空白やコメントが違うものでも探せる。全体と同じ行の並びが無いときは、1行ずつ近い行を出す。今のルートで通らない行は、一番近い駅の始まりか、同じ名前のメソッドが呼ばれる駅から推す（「推定」と出る）。見つけた場所ごとに、駅へ行く・「ここでステップを足す」（種類は行の形から if／代入／return／呼ぶ を決める）・「場所を欄に入れる」・関数の全体を見る、と、その行に出てくる材料・メモが出る。

### 検索（コード・コメント・変数名・値）と、当たった駅の点灯
環状線ページの上の検索欄（パレットの「コードから駅を探す」と同じ中身）に、コードの一部・コメントの文・変数名（`stop_balance`）・値（`1.5`）を入れると、全ファイルの全行から探して、当たった駅を図の上で黄色の点線の輪（数字は当たった行数）で光らせ、ほかの駅を薄くする。01 と 02 の両方の駅が対象で、`終了` の駅も光る。結果の表には、行ごとに「何をしている行か（代入・判定・呼び出し・定義・コメントなど）」と、その駅の何行中の何行目か・前後の駅・駅の決め方を添える。
空白でない行は、全ファイル（autodealer.py・dealer.py・card.py・player.py・players/*.py）の全行が駅に結びつく。決め方は、(1) 実行記録に出る行はその駅、(2) dealer.py は autodealer.py の `game()` の同じ流れの行、(3) 通らない行は駅の始まりの行から推す、(4) メソッドは呼ばれる駅、(5) コメント・docstring は近い行・属する関数の駅、(6) player.py は人が打つ版の土台なので 02-2 に寄せる。推した行には、その理由を表示する。
1行の一部（`Card(suit, value) for` など）を入れると、その文字を含む行を全部出し、ファイルごとの行数と、同じコードの行（autodealer.py と、その写しの dealer.py・ファイルの一番外と関数の中）をまとめて示す。dealer.py の関数（`turn_end()`）の中の行は、autodealer.py の同じ処理の行（`check_shuffle()`・`turn_end()`）の駅に合わせる。
検索しているあいだ、駅の詳しい所に「検索に関係する荷物」が出る。検索の文字と当たった行のコードに出てくる名前（`deck` → `len(deck)`、`self.stop_balance` など）を、この駅に着いたとき・この駅を出るとき・次の駅を出るときの3つで並べ、変わったマスに色を付ける。荷物とパラメータの表でも、その値を青い枠で示す（検索の色は青。図の当たった駅の輪も青）。
検索の結果から「ここでステップを足す」「＋ステップ」で足したステップには、検索した行と、おすすめの駅（★。その行の駅 → 検索で光ったほかの駅）が付き、駅を選ぶ欄の一番上にも ★ の駅が出る。「これを使って、こんなことしたい」の欄に書いたことは、材料の確認と相談・設計のプロンプトにも入る。検索した行の駅と違う駅を選んだときは「↪ この行は駅 …。ここで使うなら、その駅で値を覚えておく」と出す。足す欄にも、検索で光った駅のおすすめと「検索の行を使ってステップを足す」がある。
パレットのチップ（値・メソッド・メモ・ファイル・関数・コードにある名前）を押すと、欄に入れるのと同時に、その駅を光らせる。パレットの上に駅の帯（01 と 02）が出て、太い緑 = 手に入る駅・呼ばれる駅・中の行が動く駅、点線 = コード（コメントを除く）でその名前が出てくる駅、◆ = 入れる欄の駅。環状線の図でも同じ駅に緑の輪を付ける（「図で見る」で図へ、「× 外す」で消す）。
PC（幅 1000px 以上）では、パレットを右の列に置き、上に環状線 01 の小さな図を出す（選んだ材料・検索・旗・入れる欄の駅を、スクロールせずに見られる。02 は帯）。スマホでは、今まで通り画面の下に留める。

ステップの駅は、環状線 01 の全部の駅・ゲーム終了（return）・環状線 02 の全部の駅（autodealer.py の __main__）から選べる（`stationOptions`）。選ぶ欄には、今の位置に印が付く: ● 旗（今いる駅）・◎ 置き場所・◆ 前のステップ。「足すステップの駅」と「種類」を選んでから「ステップを足す」を押す。駅の番号は、環状線 01 は 0〜21、環状線 02 は 02-0〜（`dn`）。環状線 02 の駅や、タスク B が変えるファイルに無い駅（ゲーム側）を選ぶと、「置く所」に実際のファイル・関数と、タスク B では変えないことが出る。

相談プロンプトとメインのプロンプトには、**駅の番号表**（駅 0〜21 の名前と autodealer.py の始まりの行・戻る道・ゲーム終了・環状線 02 を使うときはその駅）が入り、AI が番号を同じように読める。自分の設計のステップが2つ以上あるときは、**ステップの駅のつながり**（`stepFlowLines`: 同じラウンドの中で届くか・間の駅・戻れず次のラウンドから効くか・game() を出入りするか）も入る。

**全体のロジックの相談**（`wholeUnit`）は、相談プロンプトの最初の単位で、「5. 自分のロジックを組む」の「全体のロジックを相談（コピー）」でも作れる。ステップを上から順に並べ（置く所・材料の確認つき）、材料の受け渡し（名前ごとに、どのステップで初期値・更新・判定・返すをするか）、触るファイル・関数、このページが自動で見つけた気になる所（新しい変数に初期値が無い・初期値より前に使っている・読む駅より後ろの駅で更新している＝効くのは次のラウンドから）を付けて、「全体として叶うか・順番と駅の順番・抜け・受け渡し・副作用・もっと単純にできるか」を聞く。単位ごとの相談とは質問が別。

パレットの **ファイル** タブは、ファイルと関数の一覧（行数・関数の行番号）で、今の位置に印が付く: ● 環状線の旗（今いる駅）・◎ 置き場所の駅・◆ いま書いている自分の設計のステップの駅。このタスクで変えるファイルが先頭に来る。押すと名前が書いている欄に入る。

**相談プロンプト**（`consultText`）は、設計を頼まずに「この変数・メソッドは、こういう処理に使えるか」を軽く聞くためのもの。自分のロジックを組んでいる単位（ステップ）で並べ、ステップに書いた材料（名前を探す）ごとに、使いたいこと・今どこにある・今の使われ方（行つき）・置き換え・変えると・メソッドなら今していることと余地、メモした材料なら初期値・こう使いたい・あるか／新しく作るか・作る所の案を付ける。同じ材料が2回目以降に出るときは「詳しい情報は ステップ N に載せた」と短くする。ステップに入れていない選んだ材料・メモした材料は、そのまま1つの単位になる。最後に「使えるか・足りない所・代わりの既存の材料・新しく作るならどこに」を聞く。単位ごとのオン・オフ、「この単位だけコピー」、各ステップ・メモ・使いたいことの欄の横の「相談をコピー」、コード全体を付けるかの切り替えがある。設計を頼むプロンプトとは別で、打っている間も同じ単位で更新される。

書くときの **使える材料のパレット**（`palette`）が、「自分のロジックを組む」の下に出る（画面の下にくっついて動く）。タブは「値（変数・引数）」「メソッド」「メモした材料」「コードにある名前」（全ファイルの def・self.…・ファイルの上の変数・関数の中の変数を、絞り込み付きで。`codeNames`）。押すと、いま書いている欄（アイデア・使いたいこと・メモ・ステップの内容）のカーソルの位置に名前が入る（カーソルは外れない）。色は、入れる欄の駅（ステップならそのステップの駅、それ以外は置き場所の駅）で、緑 = 使える・橙 = 別の駅のメソッド・赤 = まだ無い。メモの入力欄は、名前・種類・使う駅・初期値・ロジックのラベル付きの欄になった。

「4. メモ」は、変数だけでなく **新しく呼ぶメソッド**にも対応する。名前・種類（変数・値／メソッド／まだ決めていない）・使う駅・初期値・ロジックを書くと、全ファイル（autodealer.py・card.py・dealer.py・player.py・players/）と材料の一覧から自動で調べて、「既にある」（材料の一覧。使う駅で手に入るかも）・「コードにある」（材料の一覧には無いが、行がある）・「新しく作る」に分け、作る場合は作る所を出す（変数は初期値の置き場。メソッドは、定義する players/ のクラスと、呼ぶ側の game() の駅・行と、players/ の全員に要ること、タスク C になること。`memoStatus`）。プロンプトの「メモした材料」の章にも同じ内容が入る。プロンプトの字数は、メモや設計を打っている間も、各章の字数・全体の字数・お願いの番号が更新される（`refreshLive`）。

**自分でロジックを組む**ための「5. 自分のロジックを組む」がある。ステップを足して、種類（初期値を置く・値を更新する・判定する・返す・呼ぶ）・駅・内容を自分で選び、↑↓で並べ替える。ステップごとに「置く所」（その駅で、タスクのファイルのどの関数が動くか）と、内容に書いた材料・メソッド・メモした変数の確認が出る（✓ その駅で手に入る／呼ばれる・↪ 別の駅のメソッド・✗ まだ手に入らない・新しい変数は初期値のステップが要る。`stepChecks`）。プロンプトの「自分の設計」の章になり、「AI の役割」を選べる: 設計してもらう（変更後のコードまで）・自分の設計をレビュー（完成コードは書かせず、ステップごとに指摘。自分の設計があるときの最初の役割）・ヒントだけ（答えは書かず、問いと方針を段階的に）。

選んだ材料・メソッドには「使いたいこと」のメモ欄が付く（「3. 何を材料に判断する？」の下。空だと枠がオレンジ。ブラウザに残る）。プロンプトの「選んだ材料」「メソッド」に `使いたいこと:` として入り、選ばなかった材料は「今回は使わない予定」として名前だけになる。お願いには「選んだ材料ごとに、使いたいことが成り立つか」の章があり、AI は選んだものを使う前提で設計し、選ばなかったものを使うなら理由を先に示す。

プロンプトは章に分かれていて（`promptParts`）、チェックボックスでオン・オフできる。**プロンプトに入れる章**（アイデア・前提・置き場所の関数のコード・選んだ材料・ほかの材料・メソッド・メモした変数・参考実装・ファイルとインポート・コードの全体。各章の字数つき）と、**相手の AI に答えてほしい章**（お願いの 0〜7: コードと説明が合っているか・既存の材料で叶えられるか・足りない変数・変更の順番・環状線の流れ・今の決まり・全部のプレイヤー・テスト）。答えてほしい章は、オンのものだけが番号を振り直して「お願い」に並び、「この章だけ答えてください」と書く。どちらも「全部オン／全部オフ」のボタンがあり、選びはブラウザに残る。「例を読み込む」で、参考実装（weak_threshold・MIN_BET・MAX_BET）をこの流れに入れた例と、その答え（仕組みと変更の例）が出る。

3 環状線は2本ある。**01 1ラウンド**（game() の while True ＝ dealer.py と同じ流れ）と、**02 autodealer のテスト**（autodealer.py だけにある __main__。`ring2.json`。build.py が MAX だけ 2 にして本物どおりに流す `trace_main`）。02 の「1ゲーム」の駅の中が 01。2 の図の autodealer の集計の行からは 02 の駅へ行ける。

01 のルートには、ゲームが終わるまで流すもの（`full: true`。勝ち逃げで終わる・全額を賭けて残高 0 で終わる）と、プレイヤーの place_bet（players/player_simple.py 65 行）か input（131 行）を1行だけ変えたもの（`variant`。全額を賭ける・いつも stand）がある。変えた所は `variantEx` に書き、ルートの結末の下に出る。`seed` を書いたルートは、`cards` の代わりに乱数の種で混ぜた本物の山札で流す。`tail: true` は最後のラウンドだけを残す（「負けて終わる（player_simple のまま）」は種 1 で 26 ラウンド遊んで残高 0 になる最後のラウンド）。

「autodealer の1手」の下には **判断の部分** がある。`build.py` が今の players/ にある .py を全部探し（`PLAYERS`）、どのプレイヤーも同じカードの並びで1ラウンドだけ本物の autodealer.game() を流して、place_bet と input の中を通った行を順番に、その行に出てくる変数の値と一緒に記録する（`trace_decisions`。乱数は種をそろえる）。場面は「勝つ一手」「負ける一手」「勝ち逃げで終わるまで」「負けて終わるまで」の4つ。どの場面も、本当にその結果になる乱数の種を build.py が探す（プレイヤーのコードは変えない）。最後までの場面では、ゲームが終わる一手（place_bet が 0 を返す、または残高 0）まで出る。大事な行は行番号に ◆ が付き、コードの下の「◆ この一手で関わる所 ○件」を押すと、一手・環状線のどこに当たるかのカードが横に並んで出る（閉じられる）。ページでは、通った順を矢印でつなぎ、if の行に真・偽、return の行に返した値を出す。プレイヤーのファイルを足したら build.py を流し直すと、ここにも出る。

点数の計算は card.py の `Card.sum` が辞書 `card.vals` を引いて行う（`vals[card.value]`、21 を超えたら A を 1 に直す）。2 つの流れには「vals の辞書を引いて足す」手順があり、3 環状線の駅にも、その駅の手札で辞書を引いた計算（例: ♠5 → vals["5"] = 5 …）が出る。

### ゲーム終了のあと
環状線 01 の「ゲーム終了（return）」から駅 0「ゲームを用意する」へ点線でつなぐ（autodealer.py の __main__ が、MAX 回になるまで game() をもう一度呼ぶ。dealer.py は1回で終わり）。終了の駅の詳しい所に「次のゲームへ → 駅 0」がある。
緊急・悪意の旗は、最初はオフ（押すとオンになる）。
環状線の駅の詳しい所にも「画面（ターミナル）」を出す。このルートでその駅までに画面に出た行（autodealer.py の is_print = True のとき printx が出す文字。dealer.py では print で出る）を並べ、その駅で出る行を光らせる。駅 3（掛け金）・駅 8（hit / stand）には、dealer.py でキーボードで打つ所も出す。環状線 02 では、__main__ が print する結果の行（build.py が駅ごとに記録）。
荷物の黄色（この駅で変わった値）は、手札を空のリストで作った・作り直した所（駅 0・駅 1）と、パラメータが新しくできた所（駅 0 の self.…・駅 2 の self.round・駅 7 の self.dealer_card・駅 15 の self.last_dealer_hand）にも付ける。
材料（値・メソッド）には「目的（何に使うか）」があり、材料の説明・プロンプト（材料の行）・パレットで選んだ材料の説明に出る。タスク B で書き換えるのは、players/player_simple.py をコピーした players/player_xxx.py（原本は残す）。置き場所を探すの「1. どのタスク？」・置く所・プロンプト（変えてよいファイル）は、コピーの名前で出し、プロンプトに付けるコードはコピー元の今の中身。「5. 自分のロジックを組む」の「既存のロジック（今のコード）: オン／オフ」で、置き場所の駅と自分のステップの駅で動く今のコードを見られる（B は関数ごと・今していること付き、C は駅ごとの game() の行）。プロンプトに入れる章は1行ずつ（長い名前は横スクロール）。環状線の駅の「この駅のコード」は折りたたみ（開閉はこのブラウザに残る）。置き場所を探すときも、タスク B・C を選んだときと同じく、タスクの手順の番号を駅に添えて図に出す。

### 2 コンテナ・コンポーネント（と 1 コンテキスト）の手順
タスク・流れを選んで手順（番号の札・← →）を選んでいる間は、今アクティブな手順の矢印・箱・行だけを残して、ほかは全部グレーにする（ほかの手順の行は灰色の下地）。タスクを「なし」にすると元に戻る。タスクのボタンの並びの「ほかをグレーにする: オン／オフ」で、グレーをやめて全体を普通の色の強さに戻せる（選んだ手順の矢印・行の印はそのまま。このブラウザに残る）。
流れ・タスク（dealer.py で1周・autodealer の1手・勝って／負けて終わる・A・B・C）の手順の下に「画面（ターミナル）」が出て、手順に連動する。その手順で画面に出る行（打つコマンド・キーボードで打った答え・print された行・結果の行）が光り、それまでに出た行は薄く、後の行は隠れる。何も出ない手順には、その理由を出す。図のターミナルの箱も、その手順で画面に出るものがあれば光る（input・print・結果の行のどれか）。タスク外の改修にも画面がある（結果の行）。画面の中身は本物: dealer.py を 100 → hit → stand → 0 と打って流した画面（打った行と出た行の順番どおり）、python3 autodealer.py の結果の行（MAX = 4000 のまま、乱数の種を決めて流す）、is_print = True のときに game() が出す行（build.py の screens()）。箱の結果の1行も、本物の値にした。

## 道路の決まり

| 地図 | コードでは |
|---|---|
| 本線（環状線） | `autodealer.py` の `game()` の `while True` の1周 = 1ラウンド。時計回り |
| 駅 | 手札・掛け金・残高の形が変わる所と、決まる所（if） |
| 拠点とランプ | プレイヤー（players/*.py）・山札（deck）・点数の計算所（card.py）。駅から寄り道して、同じ駅に戻る |
| 近道・出口 | `continue`（次のラウンドへ）と `return`（ゲーム終了） |
| 旗 | 緊急（事故）・悪意（プレイヤーのプログラムによるずる）・速さ |

部品図は、1ラウンドで実行した行を、駅 × 役割（表示・入力・判定・流れ・データ・つなぐ・計算・状態・定義）で数えた表です。役割は `build.py` の `ROLES` が行の書き方から決めます。

## 直したとき

- コードを変えて行がずれたら `build.py` が止まるので、`ring.json` の `begin` と `anchor` を今の行に直す
- ルートを足すときは、`cards` に配る順（プレイヤー → ディーラー → プレイヤー → ディーラー → 引く順）を書く。プレイヤーは `players/player_simple.py`（16 未満で hit）
